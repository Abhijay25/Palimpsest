# Frozen Blame contracts v1

Ownership: A owns infra/wiki/extensions/PalimpsestBlame/{extension.json,ServiceWiring.php,includes/**,sql/**,i18n/**,tests/php/**}. B owns that extension's resources/** and tests/js/**. C owns tests/blame/** and .github/workflows/blame.yml. Orchestrator alone owns docs/blame/**, root integration/provenance export scripts, compose/config/loader changes and README. No cross-owner edits without coordination. Extension ResourceLoader module name ext.palimpsestBlame, resources/ext.palimpsestBlame.js + .css; pure browser helpers may be split under resources/. Backend loads module only for explicit blame action, with a discoverable navigation action on readable content pages.

Action API: action=palimpsestblame; formatversion=2. Parameters op=analyze(default)|versions|build|status; title required; revision optional positive local ID (default latest). GET read ops, POST+CSRF token for build. Return {palimpsestblame:{schema_version:1,status:ready|pending|unavailable|failed,...}}. Native API errors for malformed params/permission failures. Page/revision mismatch fails. No arbitrary remote URL inputs.

Analyze ready fields: page:{id,title,language,latest_revision_id}; snapshot:{revision_id,parent_id,timestamp,user,comment,url,diff_url,contributions_url}; coverage:{history_complete,provenance_status,source_wiki,source_page_id,source_anchor_revision_id,source_anchor_timestamp,earliest_timestamp,latest_timestamp,reasons:[]}; source_text:string; html:string (safe parsed snapshot body with annotated spans); spans:[{start,end,revision_id,token_id,lineage_ids:[stable_token_id_strings],confidence,reason?}]; revisions:[{revision_id,parent_id,timestamp,user,comment,minor,source:{wiki,page_id,revision_id,parent_id,url}|null,url,diff_url,contributions_url}]; events:[{revision_id,before,after,token_ids:[],left_token_id?,right_token_id?,ambiguous:boolean,reason?,old_start?,old_end?,new_start?,new_end?}]; algorithm:{version,semantics,limits}; mapping:{mapped_characters,unmapped_reasons:[]}. start/end and all source offsets are zero-based UTF-16, end exclusive. html mapped text spans carry data-pb-start/data-pb-end; verified full leaf coverage only. Backend can add fields compatibly; required field changes require orchestrator coordination BEFORE UI depends on them. No unsafe inline script/events, user-generated attribute HTML or generated-source guesswork.

Selection ranges (optional analyze param ranges) JSON [{start,end}] maximum64 with exact source ranges from mapped DOM. Backend returns selection:{ranges,revision_ids:[],events:[],ambiguous,reasons:[]}, filtering timeline by actual selected token ancestry and deletion anchors. UI retains exact Selection.toString separately, computes source boundaries from mapped spans, and reports unmapped segments rather than including unrelated source. Native reverse/cross-element selections use normalized Range endpoints and UTF-16 offsets. Pure UI may filter precomputed event relations but server is source of truth.

Versions params: mode=asof|before|range; from/to ISO UTC bounds, limit<=100 and opaque cursor input/continuation output when needed. Return {status:ready,mode,bounds,versions:[revision metadata newest-first],selected_revision_id:int|null,continuation:null|string,coverage}. As-of/before choose one, ranges list matching edits. Empty is an explicit empty result. UI parses only documented patterns or manual bounds, displays interpretation then applies; server validates bounds independently.

Build POST parameters are op=build,title,revision,token (+formatversion=2), without a custom JSON body. Status GET parameters are op=status,title,revision,jobid (exact lowercase). Both check job page/revision ownership. Build/status include job:{id,status,processed,total?,reason?,retryable}; no generated result is ready before complete. Browser uses actual job IDs, bounded polling and cancellation of stale navigation requests. Permission and suppression rechecks apply even to ready cached jobs.

Provenance bundle: read-only config directory $wgPalimpsestBlameProvenanceDirectory, per MW_LANG file {language}.json. Wrapper {schema_version:1,language,source_wiki,generated_at,sha256,payload:{pages:[{local_page_id,source_page_id,title,source_anchor_revision_id,source_anchor_timestamp,history_complete,revisions:[{local_revision_id,local_parent_id,source_revision_id,source_parent_id,timestamp,sha256,user,comment,minor,content_model,source_url}]}]}}. sha256 is SHA256 of canonical payload JSON (UTF8, sorted object keys, separators comma/colon, unescaped Unicode). The trusted exporter verifies C3 batch checksums/source hashes and C4 joins. Extension compares bundle records with actual local revision state; no numeric ID equality assumption. Missing imported bundle fails honestly; ordinary new local pages work without a source bundle. Document config and export invocation.

Budgets initially: synchronous<=200 revisions, <=2MiB total source, <=200k tokens across revisions; bounded diff work and <=2MiB response. Larger work must have a real bounded resumable path or explicit unsupported limit; acceptance F08 requires exercising resume. Exact implementation limits may be tightened from measured resource evidence, not to bypass fixtures.

Provenance clarification: revision.user is the observed local username for validation; source_user is an additive public original identity field. The source prefix relationship must be explained in UI. Root exporter tests live local state again after C5 before any bundle output.

Runtime installation: exporter --install copies each bundle into existing <data-root>/config/{lang}/{lang}.json. Extension loader sets Directory=/etc/palimpsest, already read-only mounted per wiki/job. No additional Docker mount is needed; reset removes these runtime-specific mappings with config while retaining acquired source caches.

Lineage clarification: IDs are stable token identities (revision:index). Replacement descendants retain removed token identities/ancestry with ambiguity where correspondence is not unique; event token_ids relate added and removed identities. Pure deletion anchors are matched against selected lineage, not only current tokens. This is necessary for multi-step replaced/deleted wording, not just latest diff.
