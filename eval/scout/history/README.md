# Scout output (fi.wikipedia, 700 pages, 198,597 revisions)

Method: s1_meta.py reads metadata only (pages are contiguous, ordered by revision) and flags edits with |delta bytes|<=320 whose parent sha1 re-occurs in a later revision ("swap") or whose page has >=12 months of later history and no sha1 restoration ("ctl"). s2_mine.py streams text (batch 100, previous text only), diffs parent vs edit, and keeps only edits where the changed whitespace-delimited tokens (<=4, <=60 chars) are all numbers/dates or all capitalised words, excluding URLs, markup, punctuation/case-only changes. s3_select.py samples.
- value_swaps (25, 25 distinct pages, 16 number / 9 name): ground truth = later revision with sha1 identical to the bad edit's parent (exact restoration). certainty high if fix summary is a revert message, else medium.
- source_corrections (5 only): value_swaps with a <ref>/URL nearby and an explicit correction/source indication in either summary, hand-picked from the 14 candidates; certainty high 1, medium 2, low 2. Fewer than target because explicit source-based corrections are rare in this data; low ones have no explicit source statement.
- controls (25, 25 distinct pages, same number/name mix): same diff filter, no sha1 restoration, new value present and old value absent in the page's final revision, >=12 months of later history.
Biases: swaps are dominated by anonymous vandalism reverted via standard messages (many obviously bogus values, e.g. 1972->20008); good-faith erroneous edits are underrepresented. Restoration by sha1 misses partial/manual corrections. Controls are not verified as correct: some persisted edits are themselves corrections (e.g. Läskikapina 1021->1921) or unnoticed errors, and last-revision check is only a text-containment test. Token filter favours short single-token changes; names with small edit distance (typos) excluded for swaps. Source corrections lack independent verification of what the cited source says.
